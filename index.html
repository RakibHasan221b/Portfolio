02 · Case study · Personal project

Planning a real trip, not a demo.

A trip-planning tool is only useful if it's honest about what it knows. I built one that reasons over real places and real weather, with a model that reports its own accuracy instead of hiding it.

Problem

Trip-planning tools either hand you generic listicles or hallucinate details with no way to check them. There's no single tool that reasons over real place data, live conditions, and an honestly-reported model.

Approach

A full-stack platform: Next.js/React/TypeScript frontend on Vercel, FastAPI backend on Render, and a Neon PostgreSQL/pgvector database. A RAG pipeline (fastembed embeddings, pgvector similarity search) grounds GPT-4o summaries in real Copenhagen places sourced from OpenStreetMap, with a live Nominatim/Serper fallback covering thin or missing listings. A two-agent CrewAI system (OpenAI GPT-4o-mini, GPT-4o) plans a real recommendation grounded in live Open-Meteo weather, using Pydantic-validated structured intent to deterministically route each request (near, far, sequential, or area) instead of relying on free-form AI tool calls, never inventing a fact it can't cite.

Result

Built and backtested a live XGBoost recommendation-confidence classifier (Optuna-tuned, MLflow-tracked) that combines offline DistilBERT sentiment with real-time semantic signals. It raised correlation with real outcomes from r = 0.171 (the previous quality-score model) to r = 0.713. Prompt quality was validated with a live A/B test.

Stack

Next.js · React · TypeScript · FastAPI · PostgreSQL/pgvector (Neon) · RAG · CrewAI · GPT-4o · Pydantic · XGBoost · DistilBERT · Optuna · MLflow

03 · Case study · Master's thesis

Reading bias at scale.

Media bias is easy to sense and hard to measure. For my master's thesis I built a system that measures it at article level, across outlets, refreshes itself every day, and serves the results live.

Problem

Bias in geopolitical news coverage is discussed constantly but rarely quantified. Manual analysis doesn't scale past a handful of articles.

Approach

An end-to-end Python pipeline: source-specific scrapers (BBC, The Guardian, The Daily Star, New Age) run daily via GitHub Actions, storing every article in a SQLite database and feeding a continuously updating corpus. TF-IDF and sentiment analysis give a baseline and pair comparable coverage; GPT-4o then scores framing, selection/omission, sourcing and tone, with an LLM-as-a-judge check on every analysis.

Result

A corpus of 8,000+ articles that refreshes itself daily, and an interactive Streamlit app where anyone can compare outlets and time periods. The main finding: South Asian outlets put humanitarian consequences first, while international outlets gave more weight to diplomacy and strategy. Graded 10 on the Danish 7-point scale (top grade 12).

Stack

Python · Pandas · SQL · GPT-4o · TF-IDF · GitHub Actions · Streamlit · trafilatura
